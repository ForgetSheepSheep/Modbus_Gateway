# STM32F030 FreeModbus 当前代码问题总结

本文按当前代码整理，覆盖三个从机工程：

| 工程 | 默认地址 | 功能 |
|---|---:|---|
| `ModbusSlave_freemodbus_adc` | `01` | PA1/PA2 ADC，LED1-3，BEEP1-2 |
| `ModbusSlave_freemodbus_io` | `02` | KEY1-3，LED1-3，RELAY1-2 |
| `ModbusSlave_freemodbus_ht` | `03` | AHT20 温湿度，LED1-3，BEEP1-2 |

串口参数统一为：`9600, 8N1, Modbus RTU`。

本文命令默认不写 CRC，因为串口助手设置为自动添加 CRC。发送时必须使用 HEX 发送模式。

---

## 1. 当前功能分工

### ADC 从机 `01`

硬件：

| 功能 | 引脚 |
|---|---|
| ADC1 | PA1 |
| ADC2 | PA2 |
| LED1 | PB11 |
| LED2 | PB12 |
| LED3 | PB13 |
| BEEP2 | PB14 |
| BEEP1 | PB15 |
| RS485_DIR | PA8 |

初始化链路：

```text
MX_GPIO_Init()
MX_DMA_Init()
MX_ADC_Init()
MX_USART1_UART_Init()
MX_TIM3_Init()
SysTickInit()
ADCDriverInit()
AppTaskInit()
```

说明：ADC 工程必须保留 `MX_DMA_Init()`，因为 USART1 MSP 中仍使用 DMA 相关配置。去掉 DMA 初始化后可能出现 Modbus 无响应。

### IO 从机 `02`

硬件：

| 功能 | 引脚 |
|---|---|
| KEY1 | PA3 |
| KEY2 | PA4 |
| KEY3 | PA5 |
| LED1 | PB11 |
| LED2 | PB12 |
| LED3 | PB13 |
| RELAY1 | PB4 |
| RELAY2 | PB5 |
| RS485_DIR | PA8 |

初始化链路：

```text
MX_GPIO_Init()
MX_USART1_UART_Init()
MX_TIM3_Init()
SysTickInit()
AppTaskInit()
```

说明：KEY 为只读输入，代码中 `KeyDriverReadState()` 按低电平按下处理，返回值 `1` 表示按下，`0` 表示未按下。

### 温湿度从机 `03`

硬件：

| 功能 | 引脚 |
|---|---|
| AHT20 | I2C1 |
| LED1 | PB11 |
| LED2 | PB12 |
| LED3 | PB13 |
| BEEP2 | PB14 |
| BEEP1 | PB15 |
| RS485_DIR | PA8 |

初始化链路：

```text
MX_GPIO_Init()
MX_DMA_Init()
MX_USART1_UART_Init()
MX_I2C1_Init()
MX_TIM3_Init()
SysTickInit()
AHT20DriverInitial()
AppTaskInit()
```

说明：AHT20 已放到独立驱动 `ModuleDriver/driver_ah20` 中，周期任务 `AHT20DriverTask()` 每 1000 ms 更新一次缓存值。Modbus 读温湿度时读取缓存，不在回调里阻塞等传感器。

## 2. 寄存器表和值定义

所有寄存器地址按 Modbus PDU 地址写，起始为 `0000`。如果上位机软件显示 `40001` 这种格式，通常 `40001` 对应代码地址 `0000`。

### ADC 从机 `01`

| 地址 | 读写 | 名称 | 值含义 |
|---:|---|---|---|
| `0000` | R/W | LED1 | `0` 关，`1` 开 |
| `0001` | R/W | LED2 | `0` 关，`1` 开 |
| `0002` | R/W | LED3 | `0` 关，`1` 开 |
| `0003` | R/W | BEEP1 | `0` 关，`1` 开 |
| `0004` | R/W | BEEP2 | `0` 关，`1` 开 |
| `0005` | R | PA1 ADC | ADC 原始值 |
| `0006` | R | PA2 ADC | ADC 原始值 |
| `0007` | R/W | 从机地址 | `1` 到 `247` |

### IO 从机 `02`

| 地址 | 读写 | 名称 | 值含义 |
|---:|---|---|---|
| `0000` | R/W | LED1 | `0` 关，`1` 开 |
| `0001` | R/W | LED2 | `0` 关，`1` 开 |
| `0002` | R/W | LED3 | `0` 关，`1` 开 |
| `0003` | R/W | RELAY1 | `0` 断开，`1` 吸合 |
| `0004` | R/W | RELAY2 | `0` 断开，`1` 吸合 |
| `0005` | R | KEY1 | `0` 未按下，`1` 按下 |
| `0006` | R | KEY2 | `0` 未按下，`1` 按下 |
| `0007` | R | KEY3 | `0` 未按下，`1` 按下 |
| `0008` | R/W | 从机地址 | `1` 到 `247` |

### 温湿度从机 `03`

| 地址 | 读写 | 名称 | 值含义 |
|---:|---|---|---|
| `0000` | R/W | LED1 | `0` 关，`1` 开 |
| `0001` | R/W | LED2 | `0` 关，`1` 开 |
| `0002` | R/W | LED3 | `0` 关，`1` 开 |
| `0003` | R/W | BEEP1 | `0` 关，`1` 开 |
| `0004` | R/W | BEEP2 | `0` 关，`1` 开 |
| `0005` | R | 温度 | 有符号值，实际温度 = 寄存器值 / 10 |
| `0006` | R | 湿度 | 实际湿度 = 寄存器值 / 10 |
| `0007` | R/W | 从机地址 | `1` 到 `247` |

温度示例：寄存器值 `00 FA` = 250，表示 `25.0 C`。如果低温出现负数，需要按 `int16_t` 解析，例如 `FF F6` 表示 `-10`，即 `-1.0 C`。

### 修改从机地址

地址写入后，设备会先用旧地址返回 `06` 写单寄存器响应，约 `50 ms` 后新地址生效。

ADC 从机当前地址 `01`，地址寄存器 `0007`：

```text
改为 02:
01 06 00 07 00 02

改回 01:
02 06 00 07 00 01
```

IO 从机当前地址 `02`，地址寄存器 `0008`：

```text
改为 04:
02 06 00 08 00 04

用新地址读全部:
04 03 00 00 00 09

改回 02:
04 06 00 08 00 02

确认读全部:
02 03 00 00 00 09
```

温湿度从机当前地址 `03`，地址寄存器 `0007`：

```text
改为 05:
03 06 00 07 00 05

用新地址读全部:
05 03 00 00 00 08

改回 03:
05 06 00 07 00 03
```

## 4. 返回值解析

### 写多个寄存器响应

发送：

```text
02 10 00 00 00 05 0A 00 01 00 01 00 01 00 01 00 01
```

典型响应：

```text
02 10 00 00 00 05
```

含义：

| 字节 | 含义 |
|---|---|
| `02` | 从机地址 |
| `10` | 功能码，写多个保持寄存器 |
| `00 00` | 起始地址 |
| `00 05` | 写入 5 个寄存器 |

### 读 IO 全部寄存器响应

发送：

```text
02 03 00 00 00 09
```

全部开后典型响应：

```text
02 03 12 00 01 00 01 00 01 00 01 00 01 00 00 00 00 00 00 00 02
```

解析：

| 寄存器 | 值 | 含义 |
|---:|---:|---|
| `0000` | `1` | LED1 开 |
| `0001` | `1` | LED2 开 |
| `0002` | `1` | LED3 开 |
| `0003` | `1` | RELAY1 吸合 |
| `0004` | `1` | RELAY2 吸合 |
| `0005` | `0` | KEY1 未按下 |
| `0006` | `0` | KEY2 未按下 |
| `0007` | `0` | KEY3 未按下 |
| `0008` | `2` | 当前从机地址 02 |

全部关后典型响应：

```text
02 03 12 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 02
```

解析：`0000-0004` 都为 `0`，说明输出寄存器已关；`0008=2`，地址仍为 `02`。

### 读温湿度全部寄存器响应

发送：

```text
03 03 00 00 00 08
```

示例响应：

```text
03 03 10 00 00 00 01 00 01 00 00 00 00 01 00 02 29 00 03
```

解析：

| 寄存器 | 原始值 | 含义 |
|---:|---:|---|
| `0000` | `0` | LED1 关 |
| `0001` | `1` | LED2 开 |
| `0002` | `1` | LED3 开 |
| `0003` | `0` | BEEP1 关 |
| `0004` | `0` | BEEP2 关 |
| `0005` | `256` | 温度 `25.6 C` |
| `0006` | `553` | 湿度 `55.3 %RH` |
| `0007` | `3` | 当前从机地址 03 |

### 读 ADC 全部寄存器响应

发送：

```text
01 03 00 00 00 08
```

响应格式：

```text
01 03 10 [0000] [0001] [0002] [0003] [0004] [0005] [0006] [0007]
```

解析：

| 寄存器 | 含义 |
|---:|---|
| `0000-0004` | LED/BEEP 当前状态，`0` 关，`1` 开 |
| `0005` | PA1 ADC 原始值 |
| `0006` | PA2 ADC 原始值 |
| `0007` | 当前从机地址 |

## 5. 本次遇到的问题统一归纳

### 问题 A：串口助手发送成 ASCII，不是 HEX

现象：日志中看到这种发送内容：

```text
30 32 20 30 36 20 30 30 20 30 38 ...
```

这不是 Modbus RTU 原始帧，而是 ASCII 字符串。例如：

| HEX | ASCII |
|---|---|
| `30` | `0` |
| `32` | `2` |
| `20` | 空格 |

也就是说实际发送的是文本 `"02 06 00 08 ..."`, 不是字节 `02 06 00 08 ...`。

处理：串口助手必须打开 HEX 发送，并确认自动 CRC 是对 HEX 字节计算，而不是对 ASCII 文本计算。正确日志应该直接以 `02 06 ...`、`03 03 ...` 这种形式出现。

### 问题 B：读寄存器高低字节反了

原因：早期读回调直接把 `uint16_t *` 指向发送缓冲区。STM32 是小端存储，会把低字节放在前面；Modbus 要求高字节在前。

错误效果：寄存器值 `1` 可能读成 `256`。

当前修复：三个工程的 `ReadRegsCb()` 都显式按大端写入：

```c
buf[2U * i] = (uint8_t)((val >> 8) & 0xFFU);
buf[2U * i + 1U] = (uint8_t)(val & 0xFFU);
```

### 问题 C：读多个寄存器时遇到不存在/不可读地址

原因：读全部时必须保证范围内每个寄存器都存在并且可读。如果从 `0000` 读 `0009` 个，IO 工程合法；ADC/HT 只有 `0000-0007`，最多读 `0008` 个。

当前范围：

| 从机 | 最大连续读命令 |
|---|---|
| ADC `01` | `01 03 00 00 00 08` |
| IO `02` | `02 03 00 00 00 09` |
| HT `03` | `03 03 00 00 00 08` |

### 问题 D：写只读寄存器会异常

只读寄存器不能用 `06` 或 `10` 写：

| 从机 | 只读寄存器 |
|---|---|
| ADC | `0005` PA1 ADC，`0006` PA2 ADC |
| IO | `0005` KEY1，`0006` KEY2，`0007` KEY3 |
| HT | `0005` 温度，`0006` 湿度 |

当前 `WriteRegsCb()` 会检查写权限和值范围，不允许写只读寄存器，也不允许 LED/继电器/蜂鸣器写入 `0/1` 之外的值。

### 问题 E：修改地址后马上用新地址读可能失败

原因：当前代码写地址寄存器后先保存参数，并设置延时切换标志。`ModbusTask()` 在约 `50 ms` 后重新初始化 Modbus 从机。

正确流程：

```text
1. 用旧地址写地址寄存器
2. 等旧地址返回写成功响应
3. 等 50 ms 以上
4. 用新地址读全部确认
```

### 问题 F：ADC/HT 曾经无响应

ADC 侧重点：

- `main.c` 中需要 `MX_DMA_Init()`。
- `main.c` 中需要 `ADCDriverInit()`。
- 只保留 ADC 相关任务和 Modbus 任务，避免无关模块影响。

HT 侧重点：

- `main.c` 中需要 `MX_I2C1_Init()`。
- `main.c` 中需要 `AHT20DriverInitial()`。
- `driver_iic.c` 使用有限超时，避免 I2C 阻塞太久导致主循环不能及时处理 Modbus。
- AHT20 周期读取，失败时不覆盖缓存值。

### 问题 G：AHT20 温度值异常

早期问题：

- AHT20 状态位判断不准确。
- 读取失败时可能覆盖缓存。
- 温湿度值容易被当作普通无符号数直接看，没除以 10。

当前处理：

- `AHT20IsReady()` 判断 busy 位 `0x80`。
- `AHT20ReadTempHumi()` 读取 6 字节原始数据并换算。
- Modbus 温度寄存器 `0005` 返回 `温度 x10`。
- Modbus 湿度寄存器 `0006` 返回 `湿度 x10`。

### 问题 H：BEEP1/BEEP2 引脚容易看错

当前 ADC/HT 代码按参考工程映射：

| 名称 | 引脚 |
|---|---|
| BEEP2 | PB14 |
| BEEP1 | PB15 |

所以寄存器 `0003` 控制 BEEP1，即 PB15；寄存器 `0004` 控制 BEEP2，即 PB14。

### 问题 I：控制回包正常但实物没动作

判断步骤：

1. 先看写命令有没有正常响应，例如 `02 10 00 00 00 05`。
2. 再读全部，看寄存器值是否已经变成 `1` 或 `0`。
3. 如果读回值已变化，但 LED/继电器/蜂鸣器实物没动作，优先查引脚映射、硬件接线、输出有效电平。
4. 如果读回值没有变化，查写地址、从机地址、HEX 模式、CRC 设置、是否写到了只读寄存器。

## 6. 当前代码关键修复点

### Modbus 地址使用 0-based

当前寄存器表从 `0000` 开始。FreeModbus 函数层不再把地址额外 `+1`，回调收到的就是主站发送的 PDU 地址。

### Modbus 读写回调统一

三个工程都使用同一套思路：

```text
ReadRegsCb:
  按地址找寄存器
  检查可读
  调 ReadCb 获取 uint16_t 值
  按 Modbus 大端写入发送缓冲区

WriteRegsCb:
  按地址找寄存器
  检查可写
  检查 min/max
  调 WriteCb 控制 GPIO 或保存地址
```

### 动态地址切换

地址寄存器写入后调用：

```text
AppParamSetSlaveAddr()
延时 50 ms
eMBDisable()
eMBClose()
ModbusSlaveInit()
```

这样做的目的是先让旧地址把写响应发出去，再切换到新地址。

### 无关代码清理

当前三个工程保留的运行逻辑：

| 工程 | 保留任务 |
|---|---|
| ADC | ModbusTask，ADC 读取 |
| IO | ModbusTask，KEY 读取 |
| HT | ModbusTask，AHT20DriverTask |

无关模块保留为桩函数或不进入任务调度，避免互相影响测试。

## 7. 推荐测试顺序

### 第一步：确认 HEX 模式

发送 IO 读全部：

```text
02 03 00 00 00 09
```

正确发送日志应该接近：

```text
发 -> 02 03 00 00 00 09 ...
收 <- 02 03 12 ...
```

如果发送日志是：

```text
发 -> 30 32 20 30 33 ...
```

说明仍然是 ASCII 发送，先改串口助手设置。

### 第二步：每个从机先读全部

```text
01 03 00 00 00 08
02 03 00 00 00 09
03 03 00 00 00 08
```

### 第三步：测试全部开/全部关

先测试 IO，因为 IO 已验证过控制链路最直接：

```text
02 10 00 00 00 05 0A 00 01 00 01 00 01 00 01 00 01
02 03 00 00 00 09
02 10 00 00 00 05 0A 00 00 00 00 00 00 00 00 00 00
02 03 00 00 00 09
```

再测试 ADC 和 HT 的 LED/BEEP。

### 第四步：测试改地址

建议只临时把 IO 从 `02` 改到 `04`，再改回 `02`：

```text
02 06 00 08 00 04
04 03 00 00 00 09
04 06 00 08 00 02
02 03 00 00 00 09
```

这样不会影响 ADC `01` 和 HT `03` 的默认地址。

## 8. 以后移植必须检查的代码点

这一节是给后续换板子、换工程、重新用 CubeMX 生成代码时看的。FreeModbus 能不能稳定跑，很多时候不是寄存器表问题，而是下面这些底层细节被覆盖了。

### 8.1 FreeModbus port 层

必须检查文件：

```text
Middleware/FreeModbus/port/port.h
Middleware/FreeModbus/port/portserial.c
Middleware/FreeModbus/port/porttimer.c
Middleware/FreeModbus/modbus_slave.c
Middleware/FreeModbus/modbus/functions/mbfuncholding.c
```

检查点：

| 项目 | 当前正确做法 | 移植风险 |
|---|---|---|
| 临界区 | `ENTER_CRITICAL_SECTION()` 使用 `__set_PRIMASK(1)` | CubeMX/移植后变成空宏，状态机容易乱 |
| 地址基准 | 回调地址按 `0000` 开始 | FreeModbus 原版常对地址 `+1`，会导致整体偏移 |
| 读写字节序 | Modbus 返回高字节在前 | 不能直接把 `uint16_t*` 指到发送缓冲区 |
| `eMBEnable()` 顺序 | 先保存回调，再使能协议栈 | 顺序反了可能空指针调用 |
| RS485 方向 | TXE 写数据，TC 后切回接收 | TXE 后马上切回会截断最后字节 |
| RXNE 处理 | 读 `RDR` 自动清 RXNE | 不要先手动清 RXNE 再读 |

当前 `portserial.c` 的关键逻辑：

```text
发送开始:
  RS485_TX_MODE
  使能 TXE

TXE 中断:
  FreeModbus 写 TDR
  如果 TXE 被关闭，说明最后一个字节已写入 TDR
  清 TC 并使能 TC 中断

TC 中断:
  最后一个字节已经真正发完
  关闭 TC
  RS485_RX_MODE
```

这个逻辑不要被简化成“发送完立刻切接收”。

### 8.2 中断优先级

STM32F030 的中断优先级资源少，当前推荐顺序：

| 中断 | 优先级 | 原因 |
|---|---:|---|
| TIM3 | `0` | Modbus RTU T3.5 定时最关键 |
| USART1 | `1` | 串口收发必须及时 |
| SysTick | `2` | 应用调度，不能压住 Modbus |
| DMA/I2C 等 | `3` | 辅助外设，优先级最低 |

移植后检查：

```text
Core/Src/tim.c
Core/Src/usart.c
ModuleDriver/driver_systick/driver_systick.c
Core/Src/dma.c
Core/Src/i2c.c
```

如果 SysTick 或 I2C 优先级高于 TIM3/USART1，容易出现偶发无响应、帧间隔判断错误。

### 8.3 初始化顺序

当前三个工程初始化顺序不同，不能随便删：

| 工程 | 必要初始化 |
|---|---|
| ADC | GPIO，DMA，ADC，USART1，TIM3，SysTick，ADCDriver，AppTask |
| IO | GPIO，USART1，TIM3，SysTick，AppTask |
| HT | GPIO，DMA，USART1，I2C1，TIM3，SysTick，AHT20Driver，AppTask |

移植注意：

- ADC 工程需要 `ADCDriverInit()`，否则 ADC 读数可能不正常。
- HT 工程需要 `AHT20DriverInitial()`，否则温湿度缓存可能一直是 `0`。
- `AppTaskInit()` 内部会初始化 Modbus，所以外设和驱动要先准备好。
- 如果 USART MSP 里保留 DMA 配置，建议在 `MX_USART1_UART_Init()` 前调用 `MX_DMA_Init()`。

当前 IO 工程没有调用 `MX_DMA_Init()`，但 `usart.c` 中仍保留 DMA MSP 配置。因为当前 FreeModbus 实际使用 USART 中断直接读写 `RDR/TDR`，IO 已验证可用。以后移植时建议二选一：

```text
方案 A：保留 USART DMA MSP 配置，则 main.c 中在 MX_USART1_UART_Init() 前调用 MX_DMA_Init()
方案 B：FreeModbus 不用 DMA，则从 USART MSP 中删除 DMA 初始化和 __HAL_LINKDMA
```

不要让 USART MSP 里有 DMA 初始化，但 DMA 时钟和中断完全没处理，这种状态最容易在换工程后变成隐蔽问题。

### 8.4 GPIO 映射

移植时先对照 `Core/Inc/main.h` 和 `ModuleDriver/driver_io/driver_io.c`，不要只看寄存器表。

当前关键映射：

| 工程 | 输出 |
|---|---|
| ADC | LED1 PB11，LED2 PB12，LED3 PB13，BEEP1 PB15，BEEP2 PB14 |
| IO | LED1 PB11，LED2 PB12，LED3 PB13，RELAY1 PB4，RELAY2 PB5 |
| HT | LED1 PB11，LED2 PB12，LED3 PB13，BEEP1 PB15，BEEP2 PB14 |

BEEP 特别注意：`BEEP1 = PB15`，`BEEP2 = PB14`。这个和直觉顺序相反，移植时最容易接错或写反。

如果写命令回包正常、读回状态也变了，但实物不动作，优先查：

```text
main.h 引脚宏
driver_io.c 映射表
GPIO 输出模式
硬件有效电平
板子实际接线
```

### 8.5 寄存器表扩展方法

以后加寄存器时，只改 `Application/app_modbusslave.c` 的表和对应回调：

```text
1. 增加 ReadCb/WriteCb 声明
2. 在 g_MbRegisterInstanceTable[] 增加地址
3. 设置 property：R 或 R|W
4. 写寄存器要设置 minValue/maxValue
5. 实现 ReadCb/WriteCb
6. 更新测试命令中的读数量
```

例如 IO 当前读全部是 `0000-0008`，数量 `0009`。如果再加一个寄存器 `0009`，读全部命令要从：

```text
02 03 00 00 00 09
```

改成：

```text
02 03 00 00 00 0A
```

如果忘了改读数量，不会读到新寄存器；如果读数量超过表中最后地址，会返回异常。

### 8.6 从机地址保存

当前地址保存到 Flash 最后一页：

```text
APP_PARAM_FLASH_PAGE_ADDR = FLASH_BANK1_END + 1 - FLASH_PAGE_SIZE
```

保存内容包括：

```text
magic
version
slaveAddr
checksum
```

移植注意：

- 换芯片容量后，确认最后一页没有和程序、参数区、Bootloader 冲突。
- 如果不想保留旧地址，整片擦除或擦掉最后一页。
- 地址范围当前是 `1-247`，不能写 `0`。
- 写地址后延时约 `50 ms` 才重新初始化 Modbus。

### 8.7 AHT20 移植注意

当前 AHT20 驱动原则：

| 项目 | 当前做法 |
|---|---|
| 地址 | 驱动传入 8 位地址：写 `0x70`，读 `0x71` |
| 初始化 | 上电延时 40 ms，发送 `BE 08 00` |
| 测量 | 周期发送 `AC 33 00` |
| 等待 | 至少等 80 ms |
| 状态 | busy 位 `0x80` 为 0 才读数据 |
| 返回 | 温度/湿度都乘 10 存到缓存 |

最容易错的是 I2C 地址：当前 `driver_iic.c` 不再左移地址，调用方已经传入 8 位地址。如果换成 HAL 常见的 7 位地址风格，必须统一改，不能两边都左移。

### 8.8 ADC 移植注意

ADC 当前寄存器：

```text
0005 = PA1 ADC
0006 = PA2 ADC
```

移植检查：

- `Core/Src/adc.c` 中是否配置了 `ADC_CHANNEL_1` 和 `ADC_CHANNEL_2`。
- `Core/Inc/main.h` 是否没有把 PA1/PA2 配成普通 GPIO。
- `ADCDriverInit()` 是否调用了校准。
- 如果读数一直为 0 或固定值，先确认 ADC 时钟、引脚模拟模式、采样通道切换。

### 8.9 CubeMX 重新生成后的复查清单

CubeMX 重新生成代码后，按这个顺序查：

```text
1. main.c 初始化顺序有没有被覆盖
2. main.h 引脚宏有没有变
3. usart.c 里 USART1 中断优先级是否仍为 1
4. tim.c 里 TIM3 中断优先级是否仍为 0
5. driver_systick.c 里 SysTick 优先级是否仍为 2
6. portserial.c 的 USART1_IRQHandler 是否还在
7. port.h 临界区是否还在
8. mbfuncholding.c 是否仍然是 0-based 地址
9. modbus_slave.c 是否先赋值回调再 eMBEnable
10. app_modbusslave.c 寄存器数量和测试命令是否同步
```

### 8.10 快速判断问题在哪一层

| 现象 | 优先检查 |
|---|---|
| 完全无响应 | 地址、HEX 模式、CRC、USART/TIM3 中断、RS485 方向 |
| 偶发无响应 | 中断优先级、临界区、阻塞任务、I2C 超时 |
| 响应少最后 1 字节或 CRC 错 | RS485 是否等 TC 后再切回 RX |
| 读值 1 变 256 | Modbus 大端字节序 |
| 写回包正常但实物不动 | GPIO 映射、有效电平、硬件接线 |
| 改地址后旧地址没反应新地址也没反应 | 等待 50 ms，确认写入值在 1-247，必要时擦 Flash 最后一页 |
| 温湿度一直 0 | I2C 初始化、AHT20 初始化、地址是否二次左移、AHT20 是否接好 |
| ADC 一直 0 | ADC 初始化、PA1/PA2 模拟输入、ADC 通道配置 |
